## 1. Skema/Type `SiteConfig`: token tema, union blok, bentuk props, validasi (Zod?)

- `SiteConfig` adalah interface TypeScript murni, **bukan skema Zod**. Tidak ada dependensi `zod` di `package.json` (dependencies hanya React 19, Tailwind 4, Zustand, Immer, dnd-kit, lucide-react, sonner, clsx, tailwind-merge, react-router-dom). `package.json`, https://raw.githubusercontent.com/buildingopen/openpage/master/package.json
- Bentuk lengkap: `SiteConfig { name: string; pages?: PageConfig[]; blocks: BlockConfig[]; theme?: Partial<ThemeConfig> }` — perhatikan `theme` bertipe `Partial`, sehingga override sebagian token diizinkan secara type-level. `src/blocks/types.ts:67-72`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/blocks/types.ts
- `PageConfig { id: string; name: string; path: string; blocks: BlockConfig[] }` — blok bisa hidup di `pages[].blocks` **atau** di `blocks` top-level; keduanya didukung. `src/blocks/types.ts:60-65`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/blocks/types.ts
- `BlockConfig { id: string; type: BlockType; variant: BlockVariant; props: Record<string, unknown> }` — `props` sengaja dibuka (`unknown`), bukan per-jenis tipe. `src/blocks/types.ts:24-29`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/blocks/types.ts
- `BlockType` = union 19 literal: `navbar, hero, features, pricing, cta, footer, testimonials, stats, faq, team, contact, newsletter, logocloud, divider, banner, content, image, video, gallery`. `BlockVariant = string` (bukan union — bebas). `src/blocks/types.ts:1-22`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/blocks/types.ts
- `ThemeConfig` = **20 field**: bg0–bg5 (6), text0–text3 (4), accent + accentDim (2), borderDefault/borderSubtle/borderHover (3), fontSans/fontDisplay/fontMono (3), radius + radiusLg (number, 2). `src/blocks/types.ts:31-58`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/blocks/types.ts
- "Skema" nyata untuk variant + props ada di katalog data `blockMetadata: BlockMeta[]` (19 entri), tiap entri berisi `type, label, description, category, variants[], defaultProps`. Di sinilah daftar variant dan props default tinggal satu-satunya sumber kebenaran. `src/lib/block-metadata.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/block-metadata.ts
- Validasi **hand-rolled** di klien: `validateSiteConfig(raw, prompt)` → `validateTheme()` (regex `/^#[0-9a-fA-F]{6}$/` untuk 14 kunci warna; font string non-kosong; `radius` 0–24; `radiusLg` 0–32), `validateBlock()` (jenis harus ada di `VALID_BLOCK_TYPES`; variant harus ada di `VARIANT_MAP`, kalau tidak fallback ke `variants[0] || 'default'`; `props = {...defaultProps, ...raw.props}`; id fallback `block-${type}-${index}-${Date.now()}`). `src/lib/generate-site.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/generate-site.ts
- Normalisasi struktur: `pages` diproses lebih dulu; jika ada `pages` tapi `blocks` top-level kosong, `blocks = pages[0].blocks` untuk kompatibilitas; jika tidak ada `pages` tapi ada `blocks`, dibungkus jadi satu halaman Home; jika tidak ada blok valid sama sekali → `getTemplateForPrompt(prompt)` (fallback deterministik). `src/lib/generate-site.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/generate-site.ts
- Tidak ada schema validator runtime (Zod/Yup/Ajv) dan tidak ada file `.schema.json` di tree repositori; validasi terjadi setelah `JSON.parse`, di sisi klien, bukan di endpoint server. `api/generate.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/api/generate.ts

## 2. `/api/generate`: prompt → parse/validasi output Gemini, retry/repair

- Handler Vercel serverless di `api/generate.ts`: hanya `POST` (405 selain itu), butuh `GEMINI_API_KEY` (500 bila kosong), body `{ prompt: string }` (400 bila tidak ada / bukan string). Model: `gemini-3-flash-preview`. `api/generate.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/api/generate.ts
- Prompt server adalah **`systemPrompt` inline di `api/generate.ts`**, bukan `GENERATION_PROMPT` di `src/lib/generation-prompt.ts`. Keduanya berbeda: versi server **single-page** (blok di top-level, "5–8 blok", "ALWAYS include navbar, hero, ≥2 content sections, CTA, footer"); versi klien **multi-page** (`pages[]`, minimal 2 halaman, 6–10 blok/halaman, `blocks` top-level kosong). `api/generate.ts` vs `src/lib/generation-prompt.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/api/generate.ts , https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/generation-prompt.ts
- Isi prompt server: schema lengkap (`name`, 20 field `theme`, `blocks[]`), daftar 19 tipe blok + variant + props, daftar ikon (`Blocks, Code, Bot, Zap, Shield, Globe, Layers, Palette, Rocket, Star, Lock, Settings`), daftar font, dua contoh theme ("Dark tech" & "Light clean"), 9 aturan, dan instruksi "Return ONLY valid JSON. No markdown, no code fences, no explanation." `api/generate.ts` (`systemPrompt`), https://raw.githubusercontent.com/buildingopen/openpage/master/api/generate.ts
- Request ke Gemini: `contents: [{ role:'user', parts:[{ text: 'Generate a website configuration for: ${prompt}' }] }]`, `systemInstruction.parts[text] = systemPrompt`, `generationConfig: { responseMimeType: 'application/json', temperature: 0.8 }`. `api/generate.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/api/generate.ts
- Parsing **tanpa validasi skema**: `data.candidates?.[0]?.content?.parts?.[0]?.text` lalu `JSON.parse(text)` langsung dan `res.status(200).json(parsed)`. Tidak ada Zod, tidak ada pengecekan tipe blok, tidak ada retry, tidak ada repair/self-correction. `api/generate.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/api/generate.ts
- Penanganan error: non-ok → `502` + body teks Gemini; tidak ada `text` → `502`; `AbortError` dari `AbortController` 30 detik → `504`; selainnya → `500`. `vercel.json` memberi `maxDuration: 60` untuk `api/generate.ts`. `api/generate.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/api/generate.ts , `vercel.json`, https://raw.githubusercontent.com/buildingopen/openpage/master/vercel.json
- Satu-satunya "jaring pengaman" ada di **klien**, `generateSiteConfig()`: (1) coba Gemini langsung pakai kunci di `localStorage['openpage-gemini-key']` via `callGeminiDirect()` (memakai `GENERATION_PROMPT` multi-page), (2) fallback ke `POST /api/generate`, (3) fallback ke `getTemplateForPrompt(prompt)`. Hasil divalidasi dengan `validateSiteConfig()`; `GenerationResult.source` bernilai `'ai' | 'template'`. Ini **fallback chain**, bukan retry/repair terhadap output yang cacat. `src/lib/generate-site.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/generate-site.ts
- Jadi: `responseMimeType: 'application/json'` + instruksi prompt adalah satu-satunya jaminan bentuk output di server; normalisasi/penyembuhan terjadi di klien setelah parse. `api/generate.ts` + `src/lib/generate-site.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/api/generate.ts , https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/generate-site.ts

## 3. Renderer JSON blok → HTML/CSS; class / data attribute untuk validator

- Editor: `src/blocks/registry.tsx` memetakan `blockRenderers: Record<string, React.ComponentType<{block: BlockConfig}>>` untuk 19 tipe; `RenderBlock` memilih komponen atau `PlaceholderBlock` (teks `"<type> block (coming soon)"`), dan setiap blok dibungkus `BlockErrorBoundary` per blok yang menampilkan UI error bila render gagal. `src/blocks/registry.tsx`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/blocks/registry.tsx
- `BlockWrapper.tsx` (hanya mode editor) membungkus blok dengan `div role="button"`, `aria-label="${block.type} block[...]"`, `aria-selected`, sebuah `<span>` berisi `block.type` (tag tipe), serta tombol move/duplicate/delete dengan `aria-label`. **Tidak ada** `data-block-id`, `data-block-type`, atau atribut `data-*` lain pada wrapper. Saat `previewMode`, wrapper menyusut jadi `<div className={isRevealed ? 'scroll-revealed' : ''}>` saja. `src/blocks/BlockWrapper.tsx`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/blocks/BlockWrapper.tsx
- Blok memakai tag semantik `<section>`, `<nav>`, `<footer>`, `<h1>/<h2>/<h3>`, `<button>`, `<form>` dengan class Tailwind yang **terikat token tema**: `bg-green`, `bg-green/10`, `bg-bg-2`, `text-text-2`, `border-border-default`, `text-green`, `@md:` / `@2xl:` container-query, serta class animasi `reveal-fade-up reveal-d1 … reveal-d8`. `src/blocks/hero/HeroBlock.tsx`, `src/index.css`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/blocks/hero/HeroBlock.tsx , https://raw.githubusercontent.com/buildingopen/openpage/master/src/index.css
- `HeroBlock` melakukan `switch (block.variant)` untuk `split | gradient | minimal | default(centered)` — pola yang sama dipakai blok lain (lihat `renderBlock` dan `renderHero` di export). `src/blocks/hero/HeroBlock.tsx`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/blocks/hero/HeroBlock.tsx
- Token tema di-aplikasikan sebagai **CSS custom properties inline** pada div canvas: `Canvas.tsx` menghitung `resolveTheme(theme)` → `themeToCSS(resolved)` dan menyebarkannya ke `style={{...cssVars}}` bersama `color: var(--color-text-0)`, `backgroundColor: var(--color-bg-1)`, `borderColor: var(--color-border-default)`. `src/editor/Canvas.tsx`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/editor/Canvas.tsx
- Satu-satunya `data-*` yang ditemukan di seluruh source yang dibaca: `data-openpage-font` pada `<link>` yang disuntikkan `useGoogleFonts()` untuk dedup font — **bukan** pada blok yang dirender. Jadi tidak ada atribut yang bisa dipakai validator HTML untuk mengidentifikasi blok; identitas blok hanya lewat tag, class Tailwind, dan `aria-*` di editor. `src/lib/useGoogleFonts.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/useGoogleFonts.ts
- Validasi di repo terjadi di level **JSON sebelum render** (`validateSiteConfig`), bukan dengan memeriksa HTML hasil render; tidak ada validator DOM/HTML di `src/` maupun `tests/`. `src/lib/generate-site.ts`, `tests/export-html.test.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/generate-site.ts , https://raw.githubusercontent.com/buildingopen/openpage/master/tests/export-html.test.ts

## 4. Implementasi ekspor HTML: inline style, Tailwind CDN, font, yang dibuang

- Entry point `src/lib/export-html.ts`: `exportSiteToHTML(config, options)` (sinkron), pembungkus async `exportToHTML`, `downloadHTML` (Blob `text/html` + `URL.createObjectURL` + `<a download>`), dan `previewHTML` (`window.open('', '_blank', 'noopener,noreferrer')` + `document.write`). `src/lib/export-html.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/export-html.ts
- Tema di-resolve dengan `resolveTheme(config.theme)`; font diambil `[theme.fontSans, theme.fontDisplay, theme.fontMono]` lalu `googleFontUrl()` melakukan dedup dan membentuk `https://fonts.googleapis.com/css2?family=X:wght@300;400;500;600;700&display=swap`. Head menyisipkan 2 `<link rel="preconnect">` (fonts.googleapis.com, fonts.gstatic.com) + stylesheet. `src/lib/export-html.ts` (`googleFontUrl`, `exportSiteToHTML`), https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/export-html.ts
- Tailwind **bukan di-bundle**, melainkan Play CDN: `<script src="https://cdn.tailwindcss.com"></script>` + `<script>tailwind.config = {...}</script>` yang memetakan token ke `colors` (`bg-0..bg-5`, `text-0..text-3`, `green.DEFAULT`/`green.dim`, `border-default/subtle/hover`), `fontFamily` (sans/display/mono) dan `borderRadius` (`DEFAULT`, `lg`). Klaim README "self-contained, zero runtime dependencies" dengan demikian tidak persis: hasil ekspor butuh internet untuk Tailwind & font. `src/lib/export-html.ts`, `README.md`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/export-html.ts , https://raw.githubusercontent.com/buildingopen/openpage/master/README.md
- `<style>` inline berisi `:root` dengan CSS custom properties (bg0–5, text0–3, green, green-dim, border 3, font-sans/display/mono, radius-default/lg), `box-sizing`, `body` margin/bg/color/font, `h1..h6` font-family, serta transisi `.faq-content` dan `.faq-chevron`. Catatan: variabel `--color-accent-rgb`, `--color-green-glow`, `--color-green-glow2` dari `themeToCSS` **tidak ikut** disertakan dalam ekspor. `src/lib/export-html.ts` vs `src/lib/theme-presets.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/export-html.ts , https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/theme-presets.ts
- Ikon bukan `lucide-react` melainkan konstanta SVG inline (`SVG_CHECK`, `SVG_CHEVRON_DOWN`, `SVG_MENU`, `SVG_SPARKLES`, `SVG_STAR_FILLED/EMPTY/10`, `SVG_QUOTE`, `SVG_SEND`, `SVG_MAIL`) plus generator `featureIconSvg()`, `logoPlaceholderSvg()`, `starRatingHtml()`, `initials()`. Tidak ada React, JSX, atau event handler React di hasil. `src/lib/export-html.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/export-html.ts
- Keamanan output: `escapeHtml()` mengganti `& < > " '`; helper `prop(props, key, fallback)` memberi default; `renderLink()` menghasilkan `<a href>` bila URL ada, otherwise `<span>`. Metadata SEO: `<title>`, `meta description`, `og:title/description/image`, `rel="icon"`, dan `<html lang>` hasil `normalizeLanguage()` (en/de/es/fr, default `en`). `src/lib/export-html.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/export-html.ts
- Analitik opsional: `gaId` → `<script async src="https://www.googletagmanager.com/gtag/js?id=...">` + `gtag('config', "<id>")`; `posthogKey` → snippet `posthog.init("<key>", { api_host: 'https://us.i.posthog.com' })`. Keduanya hanya keluar bila key ada; diuji oleh Vitest. `src/lib/export-html.ts`, `tests/export-html.test.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/export-html.ts , https://raw.githubusercontent.com/buildingopen/openpage/master/tests/export-html.test.ts
- FAQ memakai JS inline `toggleFaq(btn)` yang memanipulasi `aria-expanded`, `.faq-chevron`, `.faq-content` (`maxHeight` 500px); item pertama default terbuka. Form `contact`/`newsletter` memakai `onsubmit="return false"` — murni visual, tanpa backend. `src/lib/export-html.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/export-html.ts
- **Yang dibuang saat ekspor**: chrome editor (`BlockWrapper`), class animasi `reveal-*` / `scroll-revealed`, container-query `@md:`/`@2xl:` (diganti `md:`/`lg:`/`xl:`), utility kustom dari `index.css` (`accent-glow-*`, `card-lift`, `animate-*`, `stagger-*`), dan array `pages[]` — ekspor hanya membaca `config.blocks`. `src/lib/export-html.ts`, `src/index.css`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/export-html.ts , https://raw.githubusercontent.com/buildingopen/openpage/master/src/index.css
- **GAP penting**: dispatcher `renderBlock()` hanya menangani 13 tipe — `navbar, hero, features, pricing, cta, footer, testimonials, stats, faq, team, contact, newsletter, logocloud`. Enam tipe (`content, image, video, gallery, divider, banner`) jadi komentar `<!-- Unknown block type: ... -->` meski ada di editor. Variant yang tak didukung juga jatuh ke default: hero `minimal` → centered; features `alternating` → grid; stats `counter` → grid; testimonials `carousel` → cards (komentar "carousel skipped per spec"). `src/lib/export-html.ts` (`renderBlock`, `renderHero`), https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/export-html.ts
- Tes yang ada (`tests/export-html.test.ts`, Vitest) hanya mengecek metadata SEO/language, escaping `&lt;fast&gt;`, og:image, favicon, keberadaan snippet GA/PostHog, dan ketiadaannya saat settings kosong — **tidak** menguji cakupan blok/variant. `tests/export-html.test.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/tests/export-html.test.ts

## 5. Model data preset tema (10) & penerapan token

- Model: `ThemePreset { id: string; name: string; theme: ThemeConfig }` dan `themePresets: ThemePreset[]` berisi 10 entri: `default/Dark Minimal, ivory/Ivory, clean/Clean, sand/Sand, amber/Amber, ocean/Ocean, rose/Rosé, purple-haze/Purple Haze, slate/Slate, forest/Forest`. `src/lib/theme-presets.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/theme-presets.ts
- Setiap preset ditulis `{ ...defaultTheme, ...override }` — artinya modelnya **override sebagian token**, bukan 20 field lengkap per preset. Contoh: `ocean` tidak mengubah `radius`/`radiusLg` (warisan 8/12); `clean` memakai `fontSans = fontDisplay = 'Inter'`. `src/lib/theme-presets.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/theme-presets.ts
- `defaultTheme`: bg `#09090b → #303036`, text `#fafafa → #52525b`, accent `#22c55e` / dim `#16a34a`, border `#2a2a2f / #1f1f24 / #3a3a3f`, font `DM Sans / Space Grotesk / JetBrains Mono`, radius `8 / 12`. `src/lib/theme-presets.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/theme-presets.ts
- `resolveTheme(partial?)` = `partial ? {...defaultTheme, ...partial} : defaultTheme` — satu-satunya fungsi normalisasi theme; dipakai baik oleh Canvas maupun export. `src/lib/theme-presets.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/theme-presets.ts
- `themeToCSS(theme)` memetakan token ke CSS vars: `--color-bg-0..5`, `--color-text-0..3`, `--color-green` (= `accent`), `--color-green-dim` (= `accentDim`), `--color-green-glow`/`--color-green-glow2` (alpha `0.12` / `0.06` dari accent), `--color-border-*`, `--color-accent-rgb`, font stacks, `--radius-default`, `--radius-lg`. `hexToRgb('#rrggbb')` menghasilkan string `"r, g, b"`. `src/lib/theme-presets.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/theme-presets.ts
- `googleFontOptions` berisi 15 font (DM Sans, Inter, Space Grotesk, Poppins, Manrope, Outfit, Plus Jakarta Sans, Sora, Nunito Sans, Work Sans, Rubik, Raleway, JetBrains Mono, Fira Code, Source Code Pro). Prompt di `api/generate.ts` memakai daftar 15 yang sama; `GENERATION_PROMPT` di klien hanya 12 (berhenti di Raleway). `src/lib/theme-presets.ts`, `api/generate.ts`, `src/lib/generation-prompt.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/theme-presets.ts , https://raw.githubusercontent.com/buildingopen/openpage/master/api/generate.ts , https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/generation-prompt.ts
- Penerapan runtime: `Canvas.tsx` → `resolveTheme` + `themeToCSS` → inline `style` pada div canvas; `useGoogleFonts([fontSans, fontDisplay, fontMono])` menyuntik `<link data-openpage-font>` dan memanggil `document.fonts.load()`; `src/index.css` `@theme` mendefinisikan nilai default Tailwind v4 yang dirujuk class blok (`bg-green`, `text-text-2`, dll.). `src/editor/Canvas.tsx`, `src/lib/useGoogleFonts.ts`, `src/index.css`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/editor/Canvas.tsx , https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/useGoogleFonts.ts , https://raw.githubusercontent.com/buildingopen/openpage/master/src/index.css
- Ekspor **tidak** memakai `themeToCSS`; ia menulis ulang token ke `tailwind.config` + `<style>:root` secara terpisah (lihat bagian 4), sehingga ada dua jalur penerapan token yang harus dijaga konsistensinya. `src/lib/export-html.ts` vs `src/lib/theme-presets.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/export-html.ts , https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/theme-presets.ts

## Adapsi ke LP Generator

1. **Perluas `DesignContract` dengan `ThemeTokens` (20 field) + `variantCatalog`.** Jadikan `blockMetadata` OpenPage sebagai blueprint: satu array berisi `section_id`, `variants[]`, `defaultProps`, `image_slots`, `role`, `shape`, `upload_key` — sehingga 12 kontrak existing punya sumber variant/props tunggal seperti `VARIANT_MAP`/`DEFAULT_PROPS_MAP`. Test: untuk tiap kontrak, `variantCatalog[id]` tidak kosong dan `default_props` merupakan superset dari `props` yang dipakai renderer. (sumber: `src/lib/block-metadata.ts`, `src/lib/generate-site.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/block-metadata.ts)
2. **Port `validateSiteConfig` ke PHP sebagai lapisan sebelum `StructuredOutput`.** Pakai `isValidHex` regex 6-digit, bounds `radius` 0–24 / `radiusLg` 0–32, allowlist section ID, dan merge `{...defaultProps, ...props}`; kalau semua section gugur, lempar ke bounded re-ask yang sudah ada. Test: payload dengan `#fff`, `radius: 99`, `section_id: 'foo'` dinormalisasi/ditolak sesuai aturan tanpa exception. (sumber: `src/lib/generate-site.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/generate-site.ts)
3. **Samakan fallback variant dengan perilaku OpenPage.** Bila LLM mengirim variant di luar katalog, jangan gagalkan seluruh config — fallback ke `variants[0]` (OpenPage pakai `variants[0] || 'default'`) dan catat di log. Test: variant `'carousel'` pada section yang hanya punya `['cards']` → `cards`, status `variant_fallback=true`. (sumber: `src/lib/generate-site.ts:validateBlock`, https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/generate-site.ts)
4. **Pisahkan prompt builder menjadi mode `single` vs `multi` di `Prompts`.** OpenPage punya dua prompt yang tidak sinkron (server single-page vs klien multi-page) — hindari duplikasi itu: satu builder dengan flag mode yang tetap menyertakan daftar 12 section ID + token tema + aturan "tanpa Lorem ipsum". Test: snapshot prompt mode `single` dan `multi` keduanya memuat semua section ID dan nama token. (sumber: `api/generate.ts`, `src/lib/generation-prompt.ts`, https://raw.githubusercontent.com/buildingopen/openpage/master/api/generate.ts , https://raw.githubusercontent.com/buildingopen/openpage/master/src/lib/generation-prompt.ts)

Test: render 12 section → 12 node dengan atribut lengkap; tidak ada section yang lolos tanpa `data-lp-section`.
