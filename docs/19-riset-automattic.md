# Riset Sumber Primer: Automattic/minimalistic-site-builder

Riset ini hanya memakai sumber primer repositori: `README.md`, `src/`, `schemas/`, `config/`, `docs/`, `bin/`, `tests/`, plus `examples/` untuk payload contoh. Semua URL `raw.githubusercontent.com` di bawah memakai branch **`trunk`** (branch `main` menghasilkan 404). Semua direktori primer yang diminta tersedia; tidak ada path primer yang tidak bisa diakses. Dua dokumen `docs/design-quality-improvements*.md` adalah **kritik historis** atas versi lama pipeline (mis. menyarankan "judge murah", "page-styles step", "3–4 card recipe" yang kini sudah ada di kode) — dipakai hanya sebagai konteks, bukan sebagai source of truth; source of truth adalah kode di `src/` dan skema di `schemas/`.

## 1. Skema `siteSpec` kanonik

- File kontraknya adalah `schemas/site-spec.schema.json`, JSON Schema Draft 2020-12 dengan `$id` `https://raw.githubusercontent.com/Automattic/minimalistic-site-builder/trunk/schemas/site-spec.schema.json`; judulnya "SiteBuild canonical site spec" dan deskripsinya menegaskan field tetap menggambarkan identitas, subjek, bahasa, cakupan homepage, dan pohon halaman — **keputusan desain tidak boleh masuk ke sini**. (https://raw.githubusercontent.com/Automattic/minimalistic-site-builder/trunk/schemas/site-spec.schema.json)
- `required` tingkat atas berisi **17 field**: `name`, `slug`, `title`, `description`, `site_type`, `topic`, `area`, `audience`, `language`, `writing_direction`, `persona_name`, `email_domain`, `invented`, `subject_is_visual_work`, `animation_request`, `sections`, `pages`. (schemas/site-spec.schema.json:8-26)
- Field tetap memakai snake_case kanonik paket: `slug` bertipe string dengan `minLength: 1`, `maxLength: 60`, pola `^[a-z0-9]+(?:-[a-z0-9]+)*$`; `writing_direction` enum `ltr|rtl`; `invented` array unik dengan item enum `name|persona_name`; `email_domain` pola domain tanpa `@`/skema; `language` disarankan kode BCP-47 (`en`, `es-AR`) dan nilai normalisasi kosong berarti steps hilir mengikuti bahasa prompt. (schemas/site-spec.schema.json:27-104)
- `additionalProperties: true` di level atas secara sengaja mengizinkan fakta tambahan host seperti `hours`, `location`, `services`, atau tautan sosial; contoh lengkap `examples/site-spec.json` memuat `location` dan `hours` di luar 17 field tetap. Host dengan bentuk metadata sendiri (termasuk WordPress.com) melakukan mapping di adapter, bukan menambah alias khusus host ke paket ini. (https://raw.githubusercontent.com/Automattic/minimalistic-site-builder/trunk/examples/site-spec.json; docs/site-build-portable-pipeline.md "A host can supply the site spec")
- Pohon halaman adalah array `pages` dengan `minItems: 1`; **halaman pertama tingkat atas adalah homepage berdasarkan posisi**, bukan lewat flag; tiap item adalah `$defs/page` dengan `required: [title, slug, purpose, children]`, `children` berupa array rekursif dari `$defs/page`, `additionalProperties: false`, dan `slug` unik di seluruh pohon (generated spec biasanya dua level, runtime menerima rekursi lebih dalam). (schemas/site-spec.schema.json:$defs/page)
- Jalur host-supplied: `SiteBuilder::createProject(siteSpec: ...)` menyimpan objek kanonik hasil decode di `meta.json.site_spec`; node graf `site-spec` **tetap satu-satunya writer `siteSpec.json`** dan melakukan normalisasi deterministik yang sama tanpa satu pun panggilan LLM. Package mengekspos path melalui `Package::siteSpecSchemaPath()` dan `Package::siteSpecExamplePath()`. (https://raw.githubusercontent.com/Automattic/minimalistic-site-builder/trunk/src/SiteBuilder.php; docs/site-build-portable-pipeline.md)
- Precedensi cakupan: tanpa `multiPage`, spec yang disuplai mempertahankan seluruh pohon halamannya; `multiPage: false` eksplisit memaksa satu homepage; daftar `pages:` non-kosong mengimplikasikan multi-page dan mengganti pohon dengan daftar milik caller secara persis. Prompt pengguna tetap wajib karena langkah desain/konten membaca keduanya. (README.md "Embedding with an existing site spec"; src/SiteBuilder.php:createProject)
- Runtime intake sengaja **forgiving**: tidak ada gate validasi skema yang menghentikan build. `SiteSpecStep::normalize()` hanya mewajibkan delapan kunci inti `REQUIRED = [name, title, description, site_type, topic, area, audience, persona_name]`; kunci factual lain yang hilang diisi string kosong agar konsumen hilir bisa bergantung pada keberadaannya. (src/Steps/SiteSpecStep.php:58, src/Steps/SiteSpecStep.php:446-476)
- Repair deterministik dan warning: `name` kosong → fallback dari prompt + warning; `slug` di-slugify; `title` kosong → `name`; `sections` bukan array → `[]`; field usang `visual_vibe` dihapus dengan warning bila berisi nilai; bahasa tidak plausible → `''` + warning; `email_domain` tidak valid / tidak disebut prompt / diakui invented → dihapus + warning; kontak (email, telepon, jalan, URL) yang tidak disebut prompt dihapus untuk jalur generate, sedangkan spec host dipercaya. (src/Steps/SiteSpecStep.php:455-576)
- Normalisasi pohon: `normalizePages()` menghasilkan minimal satu halaman `Home/home` dengan `purpose` dari `description`; slug di-slugify dan dibuat unik di seluruh pohon dengan akhiran `-2`, `-3`, ...; entri sampah dibuang; slug `preview` reserved; `multiPage: false` memotong pohon menjadi halaman pertama dengan `children: []`; daftar caller lewat `forcePages()` menang persis atas hasil model. (src/Steps/SiteSpecStep.php:71, src/Steps/SiteSpecStep.php:728-804)
- Semua perbaikan ini menghasilkan baris `warnings.json` yang dikelompokkan per step id (`site-spec`) dengan format `authored=...; delivered=...; disposition=...`, dan ringkasan jumlah field yang diperbaiki ditulis ke narrator. (src/Steps/SiteSpecStep.php:207-210; src/Warnings.php:1-14)

## 2. Pipeline: langkah, urutan, tier model, dan artifact

- Pipeline bersifat **fixed deterministic sequence, bukan agentic loop**: satu step = satu eksekusi; `Pipeline::runThrough(Project, $untilId, $reporter, $onStart, $fromId)` mengurutkan step, mencatat waktu per step, mengarahkan transcript LLM ke `logs/llms/`, dan bisa berhenti di tengah atau resume dari tengah. (https://raw.githubusercontent.com/Automattic/minimalistic-site-builder/trunk/src/Pipeline.php)
- Ada dua graf: **blocks** (default; model menulis block markup langsung) dan **html-first** (model menulis HTML+CSS lalu `transform-site` mengubahnya). Dipilih lewat `--blocks-first` / `--html-first` atau env `SITE_BUILD_HTML_FIRST=1`; HTML-first dibungkus `FallbackBuildPipeline` (fallback seluruh build saat ini tidak aktif). Nama graf direkam di `meta.json.graph` agar resume memakai graf yang sama. (src/SiteBuilder.php:pipeline; src/StepComposition.php)
- Urutan graf **blocks** (29 step): `scaffold-theme` → `scaffold-plugin` → `site-spec` → `apply-identity` → `design-direction` → `ConcurrentGroup(theme-json, page-plan)` → `reconcile-palette` → `sections` → `section-rhythm` → `section-copy-dedupe` → `cta-budget` → `collect-images` → `normalize-layout` → `header-hero` → `contrast-fix` → `motion-sanity` → `fix-blocks` → `assemble-pages` → `page-styles` → `custom-motion` → `bundle-fonts` → `fonts-php` → `extract-patterns` → `finalize-theme` → `theme-screenshot` → `validate-theme`. (https://raw.githubusercontent.com/Automattic/minimalistic-site-builder/trunk/src/StepComposition.php)
- Urutan di atas bukan arbitrer: `reconcile-palette` menyelaraskan warna yang dibuat bersamaan; `collect-images` harus sebelum `fix-blocks` karena re-serialisasi menghapus alt `AI_IMAGE` pada cover; `contrast-fix`/`motion-sanity` juga sebelum `fix-blocks` agar perbaikan atribut JSON disinkronkan ke HTML oleh re-serialisasi; `assemble-pages` dan `page-styles` sesudah `fix-blocks` agar memakai markup final. (src/StepComposition.php, komentar pada `blocks()`)
- Graf **html-first** mengganti/ menambah: `design-preview`, `inner-pages-design` (membungkus `page-plan`), `splice-home-design`, `assign-image-sources`, `transform-site` (membungkus `page-plan` + `sections`), lalu `resolve-nav-links`, `fix-pages` setelah `assemble-pages`, dan `fonts-php(htmlFirst: true)`; tidak ada `reconcile-palette`, `section-copy-dedupe`, `bundle-fonts`. (src/StepComposition.php:htmlFirst)
- Fase **post-images** sengaja di luar kedua graf karena generasi gambar lambat dan networked; urutannya: `generate-images` → `theme-screenshot` (poster palette diganti hero asli) → `cover-contrast` → `extract-patterns` → `validate-theme`. Dipakai bersama oleh `bin/build.php --with-images` dan `bin/images.php`. (src/StepComposition.php:postImages; bin/images.php)
- `StepGraph` memvalidasi graf saat assembly: setiap `reads` harus dicakup oleh seed (`meta.json`) atau write step sebelumnya; id duplikat ditolak; `StepDeclaration` membatasi path menjadi segmen POSIX kanonik dengan satu glob `/*` terminal; `describe()` mengekspor graf portabel tanpa nama tool host. (https://raw.githubusercontent.com/Automattic/minimalistic-site-builder/trunk/src/StepGraph.php; src/StepDeclaration.php)
- Checkpoint CLI: `--until=<id>` berhenti setelah step itu (atau setelah seluruh `ConcurrentGroup` bila id yang disebut adalah anggotanya), `--from=<id>` melewati semua step sebelumnya dan memakai artifact di disk, `--step=<id>` = keduanya; id divalidasi dari `stopIds()` sebelum proyek dibuat. Resume dengan flag yang bertentangan dengan `meta.json.graph` dianggap kesalahan, bukan override. (bin/build.php:25-84, bin/build.php:374-399; src/Pipeline.php)
- Tier model ada di `config/models.json`: `step_tiers` memetakan 10 step LLM — `site-spec`, `design-direction-seeds`, `page-plan`, `image-prompt-repair` = **small**; `design-direction-judge`, `design-direction`, `theme-json`, `sections`, `page-styles`, `custom-motion` = **large**. Tiap provider mendefinisikan pasangan `large`/`small` (anthropic opus/haiku, openai astra/terra, xai grok/grok, openrouter kima-k3/k2.5:nitro, baseten DeepSeek-V4-Pro/GLM-5.3-Flash). (https://raw.githubusercontent.com/Automattic/minimalistic-site-builder/trunk/config/models.json)
- Resolusi model per step: `LLM_MODEL_<STEP>` (boleh diawali `transport:`) > `LLM_MODEL` / `LLM_MODEL_SMALL` > tier provider aktif; `design-preview`, `inner-pages-design`, `transform-site` tidak punya tier sehingga hanya override yang memberi mereka model; step deterministik tidak memanggil LLM sama sekali. Suhu juga per step, dengan judge sengaja `0.0` dan tidak mewarisi global. (src/StepDefaults.php)
- Files adalah source of truth antar step di `projects/<slug>/`: `Project` menyediakan `path()`, `themePath()`, `pluginPath()`, `markupFiles()` (parts + templates + plugin/pages), `logPath()`, `writeJson()`, `readJson()`, dan `writeJsonAtomic()` (staging + rename agar manifest resume tidak pernah truncata). (https://raw.githubusercontent.com/Automattic/minimalistic-site-builder/trunk/src/Project.php)
- `meta.json` di-seed `createProject()` dengan `prompt`, `provisional_slug`, `created_at`, `multi_page`, `graph`, plus opsional `pages`, `site_spec`, `design_constraints`, `writing_direction`, `form_placeholders`. (src/SiteBuilder.php:createProject)
- Artifact kunci: `siteSpec.json` (step `site-spec`), `designDirection.json` (direction + `hero_blueprint`), `aboveFold.json` (kontrak two-phase shared header/hero/page-opening), `images.json` + `images.generated.json` (fase gambar), `warnings.json` di root proyek, `pages.json`/`plugin/pages/*.html` hasil assemble, dan `logs/<step>.log` untuk detail verbose tiap step. (README.md "Build a site"; src/Project.php; docs/site-build-portable-pipeline.md)
- `warnings.json` adalah artifact machine-readable berbentuk `{ "<step-id>": ["pesan", ...] }`; `addWarnings()` menggabungkan dan mendeduplikasi pesan per step, `replaceWarnings()` mengganti satu step tanpa mengubah yang lain, dan `Warnings::value()` memotong encoded JSON ke 160 karakter untuk evidence yang ringkas. (src/Project.php:addWarnings/replaceWarnings; src/Warnings.php:1-14)
- `BuildReport` adalah ledger pasif yang merender ringkasan ke konsol **dan** `projects/<slug>/logs/project.log` (`render()`), serta menulis `projects/<slug>/build-stats.json` (`stats()`): per-step detik/token/model, wall time, jumlah request, tally gambar (generated/failed/placeholders/provider attempts/reused), tally pola, dan hitungan warning per step. `bin/build.php` menulis keduanya, termasuk setelah status completion. (https://raw.githubusercontent.com/Automattic/minimalistic-site-builder/trunk/src/BuildReport.php; bin/build.php:565-618)
- Model transport dipilih sekali oleh host (`AnthropicClient`, `OpenAiCompatibleClient`, `WpcomAiLlm`, `ClaudeCliLlm`, dll.) dan diinjeksikan sebagai `Llm`; interface hanya empat metode (`complete`, `completeJson`, `completeBatch`, `completeJsonBatch`). Conformance gate `php bin/llm-conformance.php --structural` memastikan `cached_prefixes` benar-benar masuk usage tagihan. (docs/site-build-portable-pipeline.md)

## 3. `PhpBlockFixer`: validasi, repair, fatal vs warning, dan pengaman konten

- `PhpBlockFixer` adalahcompatibility fixer Gutenberg **murni PHP**, berjalan in-process tanpa Node/`node_modules`; fakta perilaku blok diekstrak sekali dari `@wordpress/block-library@9.42.0` oleh generator Node yang di-pin lalu dibekukan ke artifact: `generated-registry.php`, `supported-blocks.php`, fixture JSON, dan golden cases. Runtime produksi tidak menyentuh Gutenberg. (docs/block-fixer-architecture.md; README.md "Breaking change")
- Discovery hanya membaca `*.html` di `templates/`, `parts/`, dan `pages/`; berkas tanpa `<!-- wp:` ditandai `skip`; daftar diurutkan agar deterministik. (src/PhpBlockFixer.php:discover)
- Tiap berkas diisolasi: transformer dijalankan berulang sampai **fixed point** dengan batas `MAX_PASSES = 5`; output identik dengan input berarti konvergen. Kegagalan satu berkas menghasilkan `FileReport(..., 'failed', ...)` dan **byte aslinya dikirim apa adanya**, bukan menggagalkan seluruh build yang sudah dibayar. (src/PhpBlockFixer.php:60-115)
- Semua penemuan dan transformasi selesai sebelum write pertama: setiap berkas yang berubah di-stage oleh `NativeStagedFileWriter` lalu di-commit sebagai deretan atomic rename; kegagalan staging membuang semua staged file, kegagalan commit membuang file ini dan sesudahnya sehingga retry aman dan konvergen. (src/PhpBlockFixer.php:118-160)
-Per pass `Serializer::transform()`: (1) `ParagraphFixer` memperbaiki markup paragraph bersarang sebelum parse dan mengecek ulang sesudah serialisasi; (2) `DefaultParser` port dari `@wordpress/block-serialization-default-parser` menghasilkan block/freeform node; freeform dipertahankan; (3) per block rekursif; (4) `DroppedContentDetector` membandingkan byte awal vs akhir. (docs/block-fixer-architecture.md "One Serializer::transform() pass")
- Nama blok tidak terdaftar mengambil jalur `serializeRawBlock()`/`core/missing` (byte asli dipertahankan) tetapi **anak yang terdaftar tetap dicek strategy**, sehingga fallback bukan terowongan untuk menghindari guard; blok terdaftar yang tidak ada di manifest `supported-blocks.php` **fails closed**. (docs/block-fixer-architecture.md)
- `AttributeSourcer` mengekstrak atribut sourced dari HTML memakai `sourceInventory` registry; `Validator` membandingkan token HTML aktual terhadap render kanonik; hanya `DeprecationAdapters` / `CompatibilityRepairs` yang sudah direview dan regression-tested yang boleh menerima perubahan, dan setiap penerimaan memancarkan baris `Repair` bertipe. (docs/block-fixer-architecture.md)
- Dua degradasi paragraph yang disetujui: root `opacity` yang tidak didukung dihapus ke opacity penuh (termasuk carryover deprecation tanpa selector), dan kombinasi legacy `align=center` + `style.typography.textAlign=justify` yang kontradiktif kehilangan alignment ambigu; keduanya memancarkan `paragraph-style-degraded`, sementara **setiap residual root style lain tetap melempar fatal**. (docs/block-fixer-architecture.md; src/Steps/FixBlocksStep.php:1455-1507)
- `SaveStrategyRegistry` mendispatch `DYNAMIC_NULL`, `INNER_BLOCKS`, `RAW_CONTENT`, `CONDITIONAL`, `MISSING_BLOCK`, `STATIC_RENDERER`; pipeline selalu **me-render ulang kanonik** sehingga input yang sudah kanonik menghasilkan byte yang sama — inilah yang membuat fixed point bekerja. (docs/block-fixer-architecture.md)
- `CoreBlockRenderer` + `SupportEngine`/`StyleEngine` mereproduksi `save.js` dan `useBlockProps.save()`; `SupportDomainGuard` fails closed pada path style di luar pohon yang direview; keluarga yang belum diimplementasikan tapi **carried** (`css`, `filter`, `color.duotone`, `variation`, `elements`, `layout`, `position`) dibawa verbatim dan disembunyikan dari validasi, tetapi `style.background` tetap fail-closed karena dikonsumsi wholesale oleh `StyleEngine`. (docs/block-fixer-architecture.md)
- `CommentSerializer` menulis delimiter dengan urutan kunci `attributeOrder` dari registry dan `JsJsonEncoder`/`JsStringCodec` yang meniru escaping Gutenberg persis, termasuk mempertahankan perbedaan `{}` vs `[]` lewat tipe `Json/*`. (docs/block-fixer-architecture.md)
- **Fatal**: direktori input tidak ada/tidak readable, berkas tidak terbaca, blok terdaftar tak didukung, signature deprecation yang belum direview, struktur/CSS malformed, kemungkinan kehilangan konten, non-konvergensi, serta kegagalan I/O, commit, artifact beku, atau programming error. (docs/block-fixer-architecture.md "Reviewed degradation boundary"; src/PhpBlockFixer.php)
- **Warning (diteruskan, build tetap sukses)**: degradasi style paragraph yang direview; blok yang dipertahankan verbatim (`Repair::PRESERVED_PREFIX`); berkas yang transformasinya ditinggalkan (dikirim byte-for-byte); kehilangan alignment class setelah attempt repair; serta catatan deterministik step dari `fix-blocks` (list kosong, caption, shape/CTA rollback, rhythm CSS). (src/Steps/FixBlocksStep.php:387-493)
- Perlindungan content loss: preflight `RootTextAlignmentConflictDetector` hanya untuk `Serializer` bawaan; `TextAlignmentRepairer` melakukan repair scoped yang memverifikasi alignment adalah satu-satunya perubahan lalu mengganti berkas secara atomik; bila repair gagal, step mengembalikan **semua** berkas theme ke byte awal dan melempar fatal. (src/PhpBlockFixer.php:repairTextAlignmentLosses; src/Steps/FixBlocksStep.php:418-435)
- Baris warning sengaja actionable: memuat `file=`, `block=`, `authored=`, `delivered=`, dan `disposition=` sehingga pass perbaikan berikutnya bisa mengonsumsinya; log lengkap tetap di `logs/fix-blocks.log`. (src/Steps/FixBlocksStep.php:1103-1158, 1400-1507)
- Sertifikasi: golden case memiliki `input/` dan `expected/` dengan inventaris berkas identik; test menuntut byte equality, lalu menjalankan fixer kedua kali dan menuntut no-op penuh; manifest + hash dibekukan dan dijaga `oracle_manifest_consistency_test.php`. Validator akhir bersifat advisory — melaporkan sisa masalah tanpa menimpa artifact yang sudah bisa dipakai. (docs/block-fixer-architecture.md "Golden fixture cases"; docs/block-fixer-oracle.md; README.md "warnings.json")

## 4. Design direction & katalog komposisi hero

- `DesignDirectionStep` memakai **tiga panggilan LLM**: seed call murah/panas menghasilkan tiga concept seed berbeda (title + satu kalimat visual + koordinat ground/register/accent), judge call besar/dingin memilih seed yang paling cocok dan tidak reflex kategori, lalu call utama mengembangkan hanya seed itu. Output `designDirection.json` berisi palette hex, type pairing/treatment, **image grade**, canvas/measure commitments, repeated-item idiom, dan `hero_blueprint` terstruktur. (src/Steps/DesignDirectionStep.php:53-70)
- Katalog hero adalah **code-owned dan reviewed**, bukan hasil prompt: konstanta `HeroComposition::RECIPES` berisi tepat tiga resep — `cinematic-safe-zone`, `foreground-split`, `layered-poster`. Tiap entri `CATALOG` memiliki metadata lengkap (`canvases`, `media_modes`, `min_images`, `max_images`, `backgrounds`, `default_background`, `fallback_background`, `header_modes`, `copy_capacity`, `mobile_transformations`, `layout_archetype`, `fallback_family`, `root_hook`, template prompt, `headline_registers`, `height_profiles`, `media_aspects`, `media_weights`, dan `defaults`). (https://raw.githubusercontent.com/Automattic/minimalistic-site-builder/trunk/src/HeroComposition.php:15-22)
- `foreground-split` adalah hasil reviewing BIGR-912: tiga resep lama (`editorial-split`, `framed-portrait`, `focal-subject-stage`) ternyata satu topologi sehingga digabung; perbedaan yang terlihat visitor kini dibawa oleh dua axis `MEDIA_ASPECTS = [portrait, landscape, square]` dan `MEDIA_WEIGHTS = [balanced, dominant]`. Resep cover mem-pin keduanya ke `landscape`/`dominant`. (src/HeroComposition.php:24-42)
- Constraint caller adalah empat kunci yang divalidasi ketat — `hero_canvas`, `allowed_hero_media_modes`, `max_hero_images`, `hero_copy_capacity` (dari flag `--hero-canvas`, `--hero-media-modes`, `--max-hero-images`, `--hero-copy-capacity`); kunci yang salah eja **fatal**, bukan diabaikan. Enum: canvas `full-bleed|framed`, mode `cover-image|foreground-image`, kapasitas `compact|standard|expanded`, `max_hero_images` integer 1–2. (src/HeroComposition.php:59-60, src/HeroComposition.php:266-290; README.md "Build a site")
- `none` bukan mode yang bisa diminta caller (tidak ada resep tanpa gambar), tetapi tetap merupakan nilai `media_mode` sah pada `hero_blueprint` sebagai hasil degradasi kehilangan media; `IMAGE_MEDIA_MODES` adalah daftar eksplisit yang mengaktifkan generasi gambar, jadi mode baru harus opt-in dengan sengaja. (src/HeroComposition.php:44-58)
- Filtering `compatible()`: canvas harus ada di `canvases`; harus ada irisan antara mode yang diizinkan caller dan `media_modes`; `max_images` resep tidak boleh melebihi `max_hero_images`; `hero_copy_capacity` dibaca sebagai **ceiling, bukan pencocokan persis** (rank `compact <= standard <= expanded`) supaya kapasitas `standard` tidak mengosongkan pool setelah penggabungan resep BIGR-912. (src/HeroComposition.php:compatible)
- Seleksi di dalam pool yang kompatibel bersifat stabil dan objektif: `sha256(json([strtolower(trim(identifier)), conceptSeed, constraints]))` diambil 8 digit hex lalu modulo jumlah pool — **tidak ada prosa prompt atau keyword industri yang ikut memutuskan**. Axis media dipilih dengan hash serupa yang di-seed dari identitas situs + concept seed + nama axis. (src/HeroComposition.php:select, selectMediaAxes)
- Prioritas override: env `HERO_RECIPE` bersifat exact dan fatal bila tidak kompatibel; `meta.json.hero_assignment` dari batch bersifat fallible — bila source bukan `batch`, recipe tidak dikenal, atau di luar pool, resep di-remap oleh selector stabil dan alasannya ditulis sebagai warning actionable di `warnings.json`; tanpa recipe bisa dipilih, `createProject()` dan `DesignDirectionStep` menolak lebih awal. (src/Steps/DesignDirectionStep.php:720-791)
- Resep diproyeksikan ke `PagePlan` lewat `planProjection()` menjadi `layout_archetype`, `allowed_backgrounds`, `default_background`, `fallback_family`; fragmen prompt resep dirender ke `hero-composition.md`, dan `designDirection.json` menyimpan `hero_blueprint` normalisasi hasil fixed point yang dijamin oleh `DesignDirectionStep::heroBlueprintFor()`. (src/HeroComposition.php:254-264; src/Steps/DesignDirectionStep.php:264-274, 2062-2085)
- `aboveFold.json` adalah kontrak two-phase untuk shared header/hero/page-opening: setelah section rhythm dan layout, `HeaderHeroStep` melakukan repair objektif saja dan mengubah artifact ke `phase: final`; konsumen berikutnya menolak phase salah; validator akhir memeriksa ulang secara advisory tanpa menimpa. Hanya `page.front && sectionIndex === 0` yang routing ke `HeroUnit` dengan `hero_blueprint` + kontrak tersebut. (docs/site-build-portable-pipeline.md "Two concurrency engines"; docs/site-build-portable-pipeline.md "Inside the wpcom path")
- `markupWarnings()` adalah pemeriksaan **advisory** (bukan rewrite) untuk jumlah media, region copy, cover langsung, region foreground, budget salinan (maksimal heading + satu paragraf), tanda baca em/en dash di H1, dan aspek gambar; semua warning berakhir dengan disposition "safe parseable hero was retained" — desain yang bisa di-parse tetap dikirim. (src/HeroComposition.php:markupWarnings)

## 5. Kebijakan generasi gambar

- `README.md` merangkum policy: `--with-images` menghasilkan **semua** gambar homepage (termasuk gambar header/footer bersama dan logo situs) serta hero existing pada halaman interior; gambar interior lain memakai placeholder lokal netral dalam bentuk dan format yang sama seperti yang ditulis; hero text-only tetap text-only. Kebijakan yang sama dipakai `bin/images.php` dan `GenerateImagesStep` di kedua graf. (README.md "Build a site")
- Image yang ditunda menyimpan spek aslinya di `images.json` dengan `status: "placeholder"`; rerun mempertahankan placeholder tanpa mengeluarkan request gambar lagi. `php bin/images.php <slug> --all` mengabaikan policy dan menghasilkan semua yang pending — satu-satunya jalan kembali ke build fully-imaged untuk eval/demo. (README.md "Build a site"; bin/images.php)
- Gambar yang **source part-nya tidak disebut plan** justru dihasilkan (bukan ditunda) dan dicatat di `warnings.json`, karena assembly menulis ulang provenance sehingga resume tidak boleh mengaburkan homepage. Ini membatasi *mana* yang dihasilkan, bukan memberi batas numerik pada gambar homepage. (README.md "Build a site"; src/InitialImagePolicy.php:unplaced; src/Steps/GenerateImagesStep.php:298-312)
- `InitialImagePolicy` membangun `eligibleSources` dari `parts/header.html`, `parts/footer.html`, dan setiap section part yang `page.front === true` atau `role === SectionRole::HERO`; `plannedSources` memuat semua section part. `shouldGenerate()` menghasilkan bila `exempt` (`generateAll`, tanpa plan, atau `role === site-logo`), bila salah satu source eligible, atau bila `unplaced()`. Logo selalu exempt karena disintesis tanpa source part tetapi terlihat di homepage. (https://raw.githubusercontent.com/Automattic/minimalistic-site-builder/trunk/src/InitialImagePolicy.php)
- `CollectImagesStep` berjalan **sebelum fix-blocks** dengan alasan eksplisit: re-serialisasi `core/cover` mereset alt menjadi `""` sehingga spek `AI_IMAGE` hanya utuh di markup mentah. Ia menulis `images.json` berisi array spek `{ filename, src, subject, pageContext, style, aspectRatio, status, sources[] }` dengan format alt kanonik `AI_IMAGE: subject | page-context | style | aspect`, dan memperbaiki spek yang salah taruh di `url`/`src`. (src/Steps/CollectImagesStep.php:23-59)
- `GenerateImagesStep` **tidak mengoleksi ulang** dari disk; ia membaca `images.json` yang sudah ada dan hanya melakukan best-effort collect bila file itu benar-benar hilang. Untuk spek yang tidak boleh dihasilkan, ia menulis `ImagePlaceholder::bytes($spec)`, menetapkan `status = placeholder` dan `url`, membersihkan `error`/`qa`, lalu menambah warning yang mencantumkan subjek authored, disposition "deferred by initial image policy", dan kenyataan bahwa spek asli tetap di `images.json`. (src/Steps/GenerateImagesStep.php:267-306; bin/images.php)
- `ImagePlaceholder::bytes()` memilih aspek lewat `GeminiImage::aspectRatio()` dan format dari ekstensi filename (`png` vs `jpg`), lalu membaca aset bundel `assets/image-placeholders/<ratio>.<format>` — dengan demikian placeholder memiliki format dan rasio aspek yang sama dengan gambar yang direncanakan. (https://raw.githubusercontent.com/Automattic/minimalistic-site-builder/trunk/src/ImagePlaceholder.php)
- Status lain: `completed` dilewati pada rerun, `failed` dicatat dengan error, aset ekuivalen bisa di-reuse dari request provider yang sama (`reused_from`), dan QA/filter keamanan menghasilkan warning tanpa menggagalkan build; penulisan `images.json` memakai `writeJsonAtomic()`, dan `images.generated.json` ditulis terakhir dengan `{"status":"completed"}`. (src/Steps/GenerateImagesStep.php:274-305, 425-462, 541-552)
- `bin/images.php <slug> [--all]` membaca graf dari `meta.json.graph` (bukan env), menjalankan seluruh `postImages()` — bukan hanya generation — sehingga cover-contrast dan theme card ikut diperbarui; tanpa kredensial LLM, langkah tetap jalan hanya saja prompt yang terkena safety filter tidak diperbaiki. (bin/images.php)
- Prompt gambar bisa di-debug terpisah lewat `php -S localhost:8080 bin/image-debug.php`: halaman memakai `GenerateImagesStep` asli terhadap proyek temporer dengan 10 contoh prompt yang bisa diedit (subject/page-context/style/aspect ratio) tanpa membangun theme. (README.md "Image prompt debugger")

## Adapsi ke LP Generator

1. **Canonical `lpSpec.json` schema (JSON Schema 2020-12) sebagai kontrak DesignContract.** Buat `schemas/lp-spec.schema.json` di plugin dengan 17 field tetap bergaya snake_case + `additionalProperties: true` untuk fakta host, dan `$defs/block` rekursif bermodel `title/slug/purpose/children` dengan slug unik dan halaman pertama = hero/homepage. Uji: fixture valid lolos; field host tambahan tidak ditolak; host adapter memetakan meta WP → bentuk kanonik tanpa alias khusus di core. (sumber: schemas/site-spec.schema.json; docs/site-build-portable-pipeline.md)
2. **`LpSpecNormalizer` deterministik di intake `StructuredOutput`.** Terapkan pola `SiteSpecStep::normalize()`: repair yang sudah direview + warning, bukan fatal gate — fallback nama, slugify, `sections: []`, `visual_vibe` dihapus, kontak tak bersumber dibuang, `multiPage: false` memotong tree, daftar caller menang persis. Uji: input malformed menghasilkan output kanonik yang idempoten (normalize(normalize(x)) === normalize(x)) plus daftar warning, dengan nol panggilan 9Router saat spec disuplai host. (sumber: src/Steps/SiteSpecStep.php:446-578, 728-804)
3. **`warnings.json` setara LP Generator.** Simpan artifact `{ stepId: [messages] }` per job (mis. `lpg_warnings_<job_id>`), dengan `addWarnings()` (dedupe, append) dan `replaceWarnings()` (untuk pass deterministik yang memiliki seluruh himpunan), serta formatter `authored/delivered/disposition` yang dipotong 160 karakter. Uji: dua perbaikan identik tidak menduplikasi baris; replace satu step tidak mengubah step lain; ringkasan `build-stats` menghitung jumlah warning per step. (sumber: src/Project.php:addWarnings/replaceWarnings; src/Warnings.php)
4. **Deterministic PHP block fixer untuk `Publisher`.** Adaptasi transaction shell: discovery terbatas, fixed point maksimal 5 pass, per-post isolation, staged write + atomic rename, batas fatal vs warning yang jelas, dan degradasi yang hanya boleh terjadi lewat resep yang direview. Uji: golden `input/expected` byte-equal; invoke kedua = no-op; berkas gagal tetap byte-identik + satu baris warning; kegagalan commit mengembalikan semua berkas. (sumber: src/PhpBlockFixer.php; docs/block-fixer-architecture.md)
5. **Checkpoint step graph di `Orchestrator`.** Beri tiap step deklarasi `reads`/`writes`, validasi graph saat assembly (seed = spec awal), serta resume `--from/--until` yang membaca artifact dari disk dan mencatat nama graf di meta job; tulis progress manifest lewat staged-atomic JSON. Uji: resume dari tengah menghasilkan byte artifact identik dengan full run; id duplikat dan read sebelum write ditolak; flag yang bertentangan dengan graf tersimpan error. (sumber: src/StepGraph.php; src/Pipeline.php; bin/build.php:374-399)
6. **Tier model per step untuk `Prompts`/`AiClient` 9Router.** Taruh `large`/`small` per provider + `step_tiers` di `config/models.json` plugin, resolusi `LLM_MODEL_<STEP>` > tier > default, dan daftar step "tierless" yang hanya mendapat model lewat override; suhu judge dikunci `0.0`. Uji: tabel resolusi untuk semua step; tidak ada step yang menyebut nama provider; step deterministik membuktikan nol request. (sumber: config/models.json; src/StepDefaults.php)
7. **Katalog komposisi hero/LP code-owned dengan seleksi hash stabil.** Tiga resep atau lebih dengan metadata lengkap, filter capability (`canvas`, `media_modes`, `max_images`, `copy_capacity` sebagai ceiling), validasi constraint ketat, hash `sha256(identifier, seed, constraints) % pool`, plus `HERO_RECIPE`-style override yang fatal bila tidak kompatibel; simpan resep + blueprint ternormalisasi di artifact DesignContract. Uji: seleksi stabil untuk seed sama; constraint tidak kompatibel gagal lebih awal; degradasi media menjadi `none` mematikan generasi gambar. (sumber: src/HeroComposition.php; src/Steps/DesignDirectionStep.php:720-791)
8. **Policy gambar + placeholder yang bisa di-regenerate.** Klasifikasikan sumber gambar (shared/hero eligible, interior defer), tulis `images.json` dengan `status: pending|placeholder|completed|failed` dan `sources[]`, hasilkan placeholder lokal yang mempertahankan format/aspek, catat warning "authored → delivered → disposition", dan sediakan mode `--all` untuk regenerate; jangan pernah mengoleksi ulang dari markup setelah fixer menghapus alt. Uji: tepat gambar mana yang menghasilkan request; placeholder punya MIME/aspek benar; rerun tidak menambah request; gambar tak terencana tetap dihasilkan dan tercatat. (sumber: src/InitialImagePolicy.php; src/Steps/GenerateImagesStep.php:267-312; src/ImagePlaceholder.php)

Smoke test adaptasi: jalankan LP yang dihasilkan di WordPress Playground, ambil screenshot full-page dengan scroll dulu (pola `bin/screenshot/screenshot.js`), dan jadikan perbandingan screenshot + `warnings.json` sebagai bukti regresi visual di CI — pola yang sama dipakai `bin/build-demos.php` untuk seluruh demo set. (sumber: bin/screenshot/screenshot.js:115-145; README.md "Build the demo set")
